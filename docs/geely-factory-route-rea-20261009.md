# 原厂热点路径兼容测试：0.2.15 支线

carlito | 2026-10-09

这是测试分支，不向主线或正式发布标签合并。本次版本名与主线相同为 0.2.15，安装序号仍为 40。

## 调查依据

实际可用吉利修改版 0.2.12 和实际发布 0.2.15 均优先 IPv4。新版就绪检查在地址选择前仅保留 site-local IPv4，可能丢失厂商 198.18/15 地址；原厂以太网未被系统列为热点接口时也可能被拒绝。

`DiPlay-20261008-191810-743.txt` 标记 0.2.14，当前尝试停在热点本地路径确认。该日志没有足以与最新 APK 对应的构建哈希，不将它当作主线 0.2.15 或最新支线成品的运行结果。

## 本次修改

1. 手动热点直接复用既有 IPv4 优先策略，不再提前剔除非 RFC1918 IPv4；仍要求系统 AP 或有效厂商路径证据，拒绝未识别 Ethernet、上游冲突、接口关闭及残留地址。
2. ECARX 当前客户端和它的本机路由源使用同一可用 IPv4规则，不以 site-local 取代实际地址归属 / 路由确认。直连仍要求同子网、唯一接口、本机 bind；IPv6 仍要求正确 scope。
3. 有完整具体路由证据的跨网段路径可以使用物理 Ethernet、网桥或无线接口；核对当前 SDK 客户端、UDP选定源、本机接口、route-get目标 / 源 / 接口、同表最长前缀、网关和本机 bind。
4. 只有 KX11 / SDK28 / kx11设备 / eth / 198.18或198.19源的已有兼容条件可以接受默认路由作为最长匹配；仍要求当前厂商客户端及上述证据全部一致。不会把默认上网网络本身当作热点。
5. 解析默认路由必须由调用者明确开启。多路径检查核对同表、同目标的最长匹配，避免无关或较短默认路由误挡具体客户端路径；冲突最长前缀和命中路径的多 nexthop 继续拒绝。
6. 沿用单一管理器、主地址、实际端口、Bonjour、iAP2 / MFi、有限参数重发、TCP看门狗、type130交接与代次保护。保留USB IPv6 / NCM和既有麦克风分离修复。

## 复核边界

没有新增连接控制器、热点开关循环、凭据猜测或全局IPv4开关。原厂路径使用保存的SSID / 口令，不能声称已自动取得真实原厂密码。

新增代码使用carlito标签。APK用已有发行签名和显式本地MFi输入构建，交付前核对实际APK的签名、包名、版本、认证资产、源码提交及修复标记。编译结果与源码复核见交付目录。

本轮未增加或运行单元测试；测试包供用户实车验证。代码编译、静态复核和成品检查不能保证厂商Binder授权、路由读取权限或实车回连一定正常。

测试时只运行一款CarPlay接收应用，保留实际热点配置与必要授权。报告需区分热点就绪、RFCOMM、手机MFi成功、StartSession发送、首个TCP、首帧与控制隧道交接。
