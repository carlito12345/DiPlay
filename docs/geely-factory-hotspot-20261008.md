## 实现边界

现有 ManualHotspotInterfaces 仅增加一个 EcarxHotspotReader。没有另一套 manager、握手、Bonjour 或自动重试流程。

1. 原厂客户端 IP 用于确认本机路由；普通 IPv4 保留真实本机地址与同子网校验，排除蜂窝、VPN、虚拟接口。IPv6 必须核对接口 scope。
   KX11 Android 9 的跨网段兼容额外要求当前 SDK 客户端、真实 eth 源地址处于 198.18/15、该源可在本机绑定、内核 `route get` 的目标/源/接口、同表覆盖当前客户端的非默认具体路由，以及位于源接口子网的实际网关全部一致。不硬编码手机网关；未知源、默认路由、跨表证据、冲突最长前缀和命中当前客户端且同表的多路径路由拒绝；无关策略表或其它目标的多路径不阻断该客户端。198.18/15 条件来自旧项目适配，是待实车验证的兼容假设，不是独立热点就绪证据。
2. SDK 缺少 IPv6 scope 或只有 IPv4、本机只见 IPv6 时，可将 SDK 当前客户端 Wi-Fi MAC 与系统 IPv6 邻居表关联。邻居查询有 400ms 上限，只有匹配的 link-local 客户端、启用的真实接口和实际本机地址能成为证据。
3. 多个原厂接口无法关联到保存的 SSID 时拒绝猜测。无当前客户端及具体路由/邻居证据的 Ethernet 继续拒绝；未恢复无条件私网或 198.18.* 例外。
4. 原厂路径使用一组保存的 SSID、密码、安全类型；不读取另一套 Android SoftAP 配置，也不把 Ethernet MAC 当作 Wi-Fi BSSID。监听、服务发现和无线邀请沿用同一主地址。
5. SDK 存在时，Android SoftAP 关闭不代表独立原厂热点关闭；仍必须通过上述通路验证。普通 WLAN 保留 Android AP 的原始关闭判定，不能因 SDK 存在而放行残留地址。已观测 Wi-Fi 上游且没有明确 AP 归属时，即使 SDK 地址与该网段重合也拒绝；明确双用 AP 可继续使用，真实原厂 Ethernet 默认接口不因此被拒绝。自动启动选项不借 Android/ADB 重建这个未知原厂热点。
6. SDK 连接和邻居进程由现有管理器释放；诊断只读取缓存。接口地址或归属来源改变会重置稳定检测。
7. 内核路由查询由 DiPlay 自身权限运行固定 `ip` 程序，每次上限 400ms；输出溢出、超时、权限不足或不明确即拒绝并释放进程。源无效、接口映射失败、跨网段、路由查询失败和绑定失败分别记录原因；地址脱敏后仍保留 family、sourceClass、availableFamilies 和 ipv4Classes，避免候选过滤再次被误读为网卡缺少 IPv4。

## 验证与实际限制

新增回归覆盖数字 IP 解析、MAC/邻居关联、IPv6 scope、地址消失、接口关闭、来源改变，以及具体跨网段路由、策略表、最长前缀冲突、默认路由拒绝和地址分类。保留网络、USB/iAP2、AirPlay、媒体、麦克风与热点设置回归。

编译、单元测试和独立源码审阅不能证明厂商 Binder 授权、SELinux 邻居/路由访问、实际热点转发或手机连接成功。UDP connect 和本机 bind 不发送包，不证明客户端可达。原厂热点完全未向 DiPlay 暴露可达接口时，程序不能凭空制造本机 IPv4，也不能把任意以太网认作热点。实际配置仅提供默认网关、隐藏源地址或拒绝路由读取时仍可能无法就绪；需要新诊断确认缺口，不能弱化成任意默认网络可用。首次连接尚无厂商客户端/通路证据时，可能仍需先让手机加入原厂热点。

版本维持 0.2.14，安装序号为 40，与主线 0.2.15 相同，支持同签名覆盖安装。测试功能基线仍为 0.2.14；主线、USB及此前麦克风修复保持独立。
